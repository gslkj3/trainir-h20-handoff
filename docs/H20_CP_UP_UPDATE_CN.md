# Devastator 完整空间修订（2026-09-27）

用户明确采用 GQA 下界 `min(8, 脚本原生 KV heads)`，上界为完整 MHA/Q heads；UP 取消固定，CP 也纳入完整空间。原有 GQA 枚举已有该规则，本次补全小头数边界和注释。GQA 原论文选择 8 个分组作为质量/推理速度折中，本实验将其作为搜索下界启发式，并不据此证明所有候选质量相等：[论文 §3.3](https://aclanthology.org/2023.emnlp-main.298.pdf)。

八例 GQA 下界按 cases8 顺序为 `8,8,8,8,2,4,8,8`。在下界至 Q heads 的范围内保留合法因数；不是把 KV heads 固定成下界。

本次解除 GPU 枚举中的 UP=1，修复候选训练入口拒绝 CP/UP 的限制，并映射至已安装 TE 的 p2p、a2a、a2a+p2p。混合分组顺序为 `[UP, CP]`。世界大小检查包含 CP×UP；对头数和序列的约束在枚举和训练入口检查。公共空间仍固定 CP=UP=1、原生 KV heads，八模型合计 296 个候选不变。

源码补丁和基准哈希位于 `patches/h20/20260927-cp-up/`。该补丁应用后不再满足上一轮“2331 个源文件全部未改”的历史状态；上一轮报告仅描述当时快照。无需重装环境。

八卡验证结果见 `reports/h20-cp-up-20260927/summary.json`。每组原生训练 10 步，保留逐 rank 梯度、更新、有效配置及完整失败日志。复现命令：

```bash
python3 scripts/run_h20_cp_up_validation.py up2 --out /opt/hbv/new-unique-up2-run
```

支持 `cp2`、`up2`、`cp2-up2`、`up2-dp2`。输出目录必须不存在；脚本检测到其他 GPU 计算进程时拒绝启动。

开放枚举与小模型训练验证不等于完整搜索已完成：CP/UP 的 H20 计算/通信 Profile、搜索到训练的一致性及全部获选配置仍需正式实验验证。结构搜索结果必须记录实际 KV heads，10 步训练不能证明质量等价。
