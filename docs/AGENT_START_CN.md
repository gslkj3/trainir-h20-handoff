# 给 H20 agent 的首条任务

请接手此仓库的 H20 八卡实验。先完整阅读 README、docs/HANDOFF_CN.md、docs/MATERIALS_CN.md、config/cases8.json 和 source_manifest.json。

本轮固定八例：LLaMA-7B-2k、LLaMA2-7B-4k、LLaMA2-13B-4k、LLaMA3-8B-8k、Qwen2-1.5B-32k、Qwen2-7B-32k、Qwen2.5-14B-8k、Qwen3-14B-4k。公共空间和完整空间都使用这八例，不因原平台失败而提前删掉三例。

顺序：材料/环境及配置检查 → 两系统真实八卡训练验证 → 八模型公共空间对比 → 八模型完整空间实验。reference 是旧代码参考，不是已完成 H20 适配的入口。优先复用其正确逻辑并做最小适配，不重新设计训练算法。

首先阅读 docs/SOURCE_RECEIPT_CN.md，用 scripts/unpack_h20_sources.py 解包已收到的源码；盘点现场和私有输入，报告缺口与实际可复用环境。源码有未提交修改，不能按上游 commit 重新下载替代。既有 5090/A100 结果和性能缓存不能成为 H20 实测数据。新的 H20 GPU 作业需在用户允许使用的八张卡上执行，不能停止别人进程。

正式测量保持1次独立训练、10步、统计6–10；通信硬件校准排除计时，计算/内存 Profile 及搜索实测墙钟计入。公共空间固定原生 GQA；Devastator 完整空间按用户修订开放 CP/UP/GQA，KV heads 下界为 min(8, 脚本原生 KV heads)，记录实际结构，不能将结构变化称为同模型吞吐收益。公共空间严格核对实际候选集合；完整空间分别报告两系统能力和范围。

所有结果先保存原始证据再汇总，失败有状态，不伪造成功。修改推送到新 h20/* 分支，提交简短中文交接记录。访问令牌只供 Git 凭证使用，禁止写入文件、日志、远程 URL 或提交。

解包目录 work/ 不入 Git。对源码的修复请保存为 patches/h20/ 下可复用的补丁，并注明基准快照 SHA256；新启动器、协议和结果摘要可以正常提交，禁止将含输入的整个工作目录推送。
